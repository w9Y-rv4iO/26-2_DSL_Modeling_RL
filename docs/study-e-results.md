# 스터디 E — 결과 (RL로 맵을 만든다 · LoL식 스킬)

사전등록: [`study-e-protocol.md`](study-e-protocol.md) · 스킬 세부:
[`skill-balance.md`](skill-balance.md) · 코드·원자료: `mapstudy/README.md`

주지표는 **맵별 `balance_error = |도망자 승률 − 0.5|`** 이며, 맵 집합의 점수는
`balance.aggregate()`의 **평균/중위/최대/RMS** 로 읽는다. **승률의 평균은 지표가
아니다** — 부호가 있는 편차는 상쇄되고 거리는 더해진다(§6.1).

모든 수치는 report 단계(240라운드 · 120초). search 단계(24 · 60초)는 비교용이며
**결과로 인용하지 않는다**(§6.2).

## 1. 한 줄 요약

| 질문 | 답 |
|---|---|
| 기하 구조가 균형과 상관하는가 (H3) | **그렇다** — 14개 지표 중 가족 수준 검정 **8개** 생존, \|rho\| 0.35–0.59 |
| 기하 구조로 균형을 **예측**할 수 있는가 | **약하게만** — 누출 없는 grouped R² **0.07–0.24** (행 섞기로는 0.49로 부풀려짐) |
| PPO가 무작위·무방향 변이보다 나은가 (H1) | 방향만 맞고 **유의하지 않다** (p 0.11 / 0.14) |
| PPO가 국소탐색보다 나은가 (H2) | **아니다.** 담금질이 이긴다. 4.6배 예산에서도 학습 흔적 없음 |
| 스킬을 켜면 균형이 좋아지는가 | 설계 그대로는 **나빠진다**(0.360). 튜닝 후 **0.141** vs 스킬 OFF 0.188 |
| 출시 설정에서 맵 탐색이 작동하는가 | **작동한다** — 0.146 → **0.121**, 최고 맵 Loops 0.004 |

**가장 방어 가능한 주장**: 이 게임의 균형은 **맵에 있다**. 등록된 7개 맵 중
5개가 승률 0.000, 1개가 0.083에 붙어 있었고(§5.1), 탐색은 통계적으로 0.5와 구별되지 않는
맵을 찾아낸다. **가장 정직한 실패**: 그 탐색을 RL로 하면 담금질보다 못하다.

## 2. H3 — 기하 구조와 균형

### 2.1 상관 (생존)

가족 수준 정확 무작위화 검정, Holm 보정, 가족 14개(`wall_frac ≡ 1 − floor_frac`
이므로 15개가 아니다), 독립 단위 82개, ICC 0.355 → **유효 n 97**:

| 지표 | rho | 해석 |
|---|---|---|
| `openness_std` | **+0.591** | 열린 곳과 좁은 곳이 섞인 맵이 불균형하다 |
| `station_spread` | −0.551 | 발전기가 흩어져 있을수록 균형에 가깝다 |
| `sight_mean` | +0.548 | 시야가 길면 술래가 이긴다 |
| `diameter` | −0.540 | 큰 맵이 균형에 가깝다 |
| `mean_pair_dist` | −0.529 | |
| `mean_degree` | +0.439 | |
| `openness_mean` | +0.425 | |
| `exit_spread` | −0.352 | |

행 수준 검정으로는 10개, 가족 수준으로는 **8개** 생존. 탈락한 둘은 가장 약한
`floor_frac`(0.336)과 `spawn_gap`(0.311)이다.

**생존 지표들은 심하게 공선적이다** — 사실상 "열린 곳 대 복도" 한 축을 여러 번
발견한 것이고 PCA를 돌리지 않았다. 또 150개 맵 중 47개가 승률 정확히 0.000,
0.5 초과가 12개뿐이므로 이것은 **"기하 구조가 승률을 설명한다"** 이지
"균형을 설명한다"가 아니다.

### 2.2 예측 (붕괴)

대리모형 교차검증. 데이터셋 150행 = 등록맵 13 + **그 13개의 변이 68** + 독립
추첨 69. 행 단위로 폴드를 나누면 부모와 1-편집 변이가 갈라져 앉는다 — 누출이다.

| 모형 | 행 섞기 (부풀려짐) | **가족 단위** (폴드 시드 0–3 평균) | 누출 |
|---|---|---|---|
| ridge | +0.235 | **+0.125** (sd 0.250) | +0.109 |
| knn k=5 | +0.348 | **+0.243** (sd 0.028) | +0.105 |
| gbm d2×200 | +0.492 | **+0.071** (sd 0.125) | **+0.421** |

**GBM은 1위가 아니라 최하위다.** 겉보기 R²의 86 %가 가족 내 암기였다.
`train.REFINE_SURROGATE_KIND`는 이 때문에 GBM에서 **ridge로 교체**됐고,
grouped 추정에서 ridge보다 낮은 모형을 기본값으로 둘 수 없다는 테스트를 걸었다.
knn이 grouped 최고(+0.243, 분산도 최소 — 관계가 **국소적**이라는 뜻)이지만
"모형"이 데이터셋 전체이므로 채택하지 않았다.

## 3. H1·H2 — 맵을 만드는 탐색기 비교

예산은 **실제 시뮬레이션 30회**/팔·시드로 동일(사전등록 §3.3.1의 재정의),
시드 4개, report 단계:

| 팔 | 중위 `balance_error` |
|---|---|
| `anneal` | **0.079** |
| `ppo` | 0.119 |
| `ppo_surrogate` | 0.121 |
| `hillclimb` | 0.204 |
| `mutate` | 0.215 |
| `random` | 0.233 |
| `anchor` | 0.125 — **n=1, 13개 맵의 최소값, 선택 수축 0.000** |

**어느 쌍도 유의하지 않다**(4v4 순열검정 바닥 0.0286; ppo−random 0.114,
ppo−anneal 0.971, 11개 쌍 최소 p 0.114). `anchor`는 팔이 아니다 — 탐색
팔들은 search→report에서 평균 **+0.083**(24/24 모두 비음수)을 잃는데 anchor는
0을 잃으므로, "ppo 0.119 대 anchor 0.125"는 수축을 낸 쪽과 안 낸 쪽의 비교다.

**최고 맵**: `hillclimb` 시드 0(Mansion 출발), `balance_error` **0.021**
(승률 0.521, 95 % CI [0.458, 0.583] — 0.5와 **구별되지 않는다**).
단, 26개 팔·시드 최종물의 **최소값**이며 **스킬 OFF** 측정이다.

### 3.1 H2가 실패한 이유 — 두 단계로 밝혀졌다

1. **사전등록의 예산 정의가 결함이었다.** "맵 채점 횟수 동일"은 `hillclimb`에
   30회의 수락/기각 판정을, PPO에는 **30 에피소드**(에피소드당 편집 40회)를
   준다. PPO는 30 에피소드로 아무것도 배우지 못한다. §5 hold-out이 확증:
   학습된 결정론 정책이 예산 12 중 **[1,1,0,0,1,0]** 회만 편집 — 무편집을
   학습했다
2. **무편집 붕괴의 절반은 보상 설계 버그였다.** 예산을 쓰는 확정 비용 0.224
   (그중 **0.180이 거절 벌점** — 원래 주석이 빠뜨린 항)에 대해 종단 보상의
   표준오차는 1.02. 게다가 종단값은 `reset()`이 정하는 **수준**(−1.67 ~ −5.00)
   이라 30 에피소드로는 학습 불가. 에피소드별 가산 상수
   `terminal_baseline`(순서 불변 증명됨)으로 수정 → §5 편집이
   **[7,8,11,3,7,10]** 로 회복

### 3.2 대리모형 학습 (3b) — 더 많은 대리는 더 많은 신호가 아니다

`ppo_surrogate` − `ppo` = **+0.002, p = 0.829**. 대리모형 3,600 에피소드가
실제 30 에피소드와 **구별되지 않는 정책**을 만들었다. DAgger 정제 3라운드로
격차가 0.170 → 0.082로 좁아지고 OOF R²가 0.492 → 0.682로 오르지만(둘 다 행
섞기 추정), 닫히지 않는다.

### 3.3 비동일예산 프로브 (3c) — 판정 (A)

실제 보상, 동일예산의 **4.6배**(139/137 채점 — 요구한 50~80배는 채점당 40.5 s
단일프로세스 CPU라 구매 불가). **팔이 아니며** `analyze.py`가 이름으로 모든
팔 간 검정에서 제외한다.

- `balance_error` **평탄**: rho −0.018 / −0.007 (p 0.83 / 0.93). n=139에서
  rho의 SE가 0.085이므로 95 %에서 |rho| < 0.17 — "작은 효과가 숨어 있을 수도"가
  아니다
- **편집 횟수는 유의하게 감소**: rho −0.297 / −0.451 (p 0.0006 / **≤ 0.0002**,
  후자는 1/5001 = 순열 바닥), 15회 → 11.7 / **5.5**. 기울기 신호는 있고
  **목표의 반대를 가리킨다**
- 병목은 **신용 배분**이다: 40회 편집을 덮는 스칼라 하나
- 남은 것: 50~80배 영역, 하이퍼파라미터(`ent_coef`는 바로 이 붕괴를 막으려
  고른 값), 시드 2개. 따라서 판정은 "**이** 예산·보상·하이퍼파라미터에서 (A)".
  다음 실험은 채점을 늘리는 것이 **아니라** 편집별 보상이나 훨씬 짧은 지평

### 3.4 대리모형 해킹 — 어디서 일어나는지가 핵심

| 측정 대상 | 실제 − 예측 | n | t |
|---|---|---|---|
| §5 hold-out (선택 없음) | +0.007 (SE 0.048) | 6 | +0.1 |
| 학습 풀 (정책이 고른 분포) | +0.070 / +0.055 (SE 0.011 / 0.010) | 139 / 137 | **+6.1 / +5.6** |

즉 해킹은 **미지의 기하 구조**의 성질이 아니라 **정책이 향하는 분포**의
성질이다. hold-out은 선택 없는 검정이지만 n=6이라 어느 쪽으로도 미결.
(이전 판은 채점 **1회**의 SE 0.102를 139개 **평균**의 잣대로 써서 실재하는
효과를 기각했다 — 9~10배 과대한 잣대였다.)

### 3.5 일반화 (§5)

같은 6개 출발맵, 편집 예산 동일, 양쪽 모두 report 채점:
`ppo` − `hillclimb` = **+0.081** (부호뒤집기 p 0.188, 바닥 0.031), ppo 승 1/6.
프로브 판본은 +0.049 (p 0.281), 편집 **[3,1,1,0,1,1]/12** — 무편집 붕괴가
돌아왔다. 출발맵보다 **나빠진 것 4/6**(report 대 report 기준: Lv3·Atrium·
Spiral·Loops). 요약: **믿음은 전이되고 균형은 전이되지 않는다.**

## 4. 스킬 — LoL식 액티브 4종

`journey`(Bard E) · `rewind`(Ekko R) · `stasis`(Bard R) · `destiny`(TF R).
16개 조절 가능 dial, **전부 live**(궤적 해시로 검증, §[skill-balance.md] §6.5).

| 설정 | 평균 \|err\| | 라운드 |
|---|---|---|
| 스킬 OFF | 0.188 | 40.1 s |
| **설계 그대로** | **0.360** | 17.5 s |
| `PLAYABLE_TUNING` (기본) | **0.141** | ~23 s |
| `BALANCED_TUNING` | **0.078** | 25.0 s |

**설계 그대로의 스킬은 게임을 덜 공정하게 만든다** — 0.360 대 0.188. 43초
라운드가 12초로 붕괴한 것은 균형이 아니라 게임이 사라진 것이다.

### 4.1 출시 결정 — 두 튜닝의 실제 교환

`BALANCED`가 숫자는 좋지만 `DESTINY_REVEAL: 0.0`으로 **게이트를 조준 불가**로
만들어 얻는다(게이트 해결 0.08–0.16회/라운드 대 0.44–1.02). 측정된 스윕 전체에서
**0.12보다 좋은 모든 설정은 게이트를 못 쓰게 해서 그렇게 된다.**

`PLAYABLE`을 기본으로 택한 근거는 **게임플레이뿐**이다: destiny는 이 스킬셋이
구현하려던 4종 중 하나이고, `PLAYABLE`은 **어느 스킬을 빼도 균형이 좋아지지
않는 첫 튜닝**이다(journey +0.018, rewind +0.339, stasis +0.077 — search 단계;
destiny +0.005 — report).

**균형 근거로는 방어되지 않는다.** 이전 판은 "맵 탐색이 0.021에 닿으니 0.068은
기하가 메운다"고 적었으나 대응 비교에서 뒤집힌다:

    BALANCED, 맵 탐색 없음, 7맵 평균 ......... 0.078
    PLAYABLE + 채점 30회 맵 탐색, 14런 ....... 0.121

`PLAYABLE`에서 맵을 탐색해도 destiny를 지워서 얻는 것을 회복하지 못한다.
0.021은 **한 맵**, 26개 팔·시드의 **최소값**, **스킬 OFF** 측정이다.
`PLAYABLE` 선택은 균형을 실제로 지불하고 네 번째 작동하는 스킬을 산다 —
**측정이 아니라 설계 선호**이며, 숫자가 중요하면 `BALANCED`로 바꿔야 한다.

### 4.2 세 번의 설계 실패와 그 원인

1. **거절된 캐스팅이 그 틱의 이동을 먹었다**(엔진 버그). 사거리를 줄이면
   127회 요청 / 127회 거절 = 라운드의 **37 %를 제자리에 서 있었다**. "사거리를
   줄이면 도망자에 +18 pp"는 전부 이 정체였고, 고친 뒤 **뒤집힌다**
   (0.444 → 0.236) — 짧은 사거리는 실제로는 술래 버프다
2. **dial 3개가 죽어 있었다.** `ChasePolicy.STASIS_CAST = TILE * 4.5`가
   사거리를, 모듈 스코프 `DESTINY_MAX_DIST` import가 밴드를, 그리고
   `destiny_landing`이 `PREFERRED` 거리 후보만 남겨 `DESTINY_MIN_DIST`를
   무력화했다(13개 맵 4,895개 바닥 위치 **전부**에서 무력). 180/200/320 px가
   **비트 단위로 동일한** 라운드를 냈다. 지금은 16/16 live
3. **`journey`가 소유자에게 손해였다** — 1.03회/라운드 캐스팅하면서 제거하면
   Lv3 승률이 +4.6 pp 올랐다. 원인은 설계가 아니라 정책: 통로가 대칭인데
   `FleePolicy`가 **궁지에 몰렸을 때만**, 즉 술래가 그 방향에 있을 때만 파냈다.
   BFS 이득으로 가격을 매기자 +2.9 pp가 됐다. 단 `journey`의 부호는
   **키트 의존적**이다(destiny가 살아 있으면 −0.007, 죽으면 +0.025) — 분산
   레버이므로 맵별 지표로만 옳게 읽힌다

### 4.3 destiny 재설계 — 균형 중립까지

원인: 게이트가 즉발·무음·반격 불가였고, **이미 술래가 우세한 맵에서 가장
강했다**(제거하면 Warren 0.208 → 0.500, Atrium 0.125 → 0.333) — 즉 가장 줄여야
할 오차를 키웠다. LoL의 커밋 비용을 복원했다: 1.5초 **채널**이 술래를 묶고,
착지점을 **채널 완료 시점에** 다시 계산하며(움직인 도망자는 따라오지 않는다),
도망자에게 표식을 알린다(관측 슬롯 53).

결과: 게이트 해결 0.08–0.16 → **0.44–1.02회/라운드**, 절제 부호가 **−0.089에서
+0.005로 역전**. 정직한 표현은 "**균형 중립**"이며 "유익"이 아니다(n=240에서
+0.005는 0과 구별 불가).

## 5. 규칙과 프로토콜에서 나온 부수 결과

### 5.1 승률 바닥의 상당 부분은 정책이 아니라 규칙이었다

스터디 A~D는 "이 게임에서 승률은 바닥에 붙는다"를 정책의 성질로 기록했다.
그런데 B·D의 `required_generators=3`은 **Lv3에서만** "5개 중 3개"다. 발전기가
3개뿐인 Arena·Corridors·Pillars·Mansion에서는 "전부"로 해소되어, v2가 없애려
한 v1 규칙으로 되돌아간다. 규칙을 **맵이 선언한 수의 분수**로 바꾸자
(0.60 / 0.75, Lv3에서 정확히 3과 3으로 해소되어 B·D와 비교 가능):

    절대 3/3 규칙: 등록 7개 중 **5개**가 승률 0.000 (Lv2 0.083, Lv3 0.333)
    분수 규칙:     등록 13개 중 **Lv1 하나만** 0.000, Foundry 0.625

### 5.2 search 시계는 순위를 보존하지만 절대값을 보존하지 않는다

n=120/셀: 순위는 두 시계에서 **동일**(탐색이 하는 대응비교에 필요한 성질),
편향은 **한 방향**(짧은 시계는 항상 낮게 본다 = 하한). 그러나 **균일하지 않다**:
Spiral은 +0.092(약 2 SE) 움직이는데 교착이 많아 긴 시계가 timeout을 escape로
바꾸기 때문이다(0.67 → 0.55). 즉 그런 맵에서 60초는 **다른 게임**을 재고 있다.
따라서 두 단계 규칙은 비용 절감이 아니라 **타당성 요건**이다.

## 6. 이 연구가 스스로 만든 세 가지 함정 (전부 실측으로 정량화)

### 6.1 승률의 평균은 균형이 아니다

스킬 스윕이 **승률 평균**으로 튜닝을 골라 0.458("거의 완벽")을 보고했다.
등록된 지표로 다시 채점하면 같은 설정이 **0.241 — 스킬 OFF(0.187)보다 나쁘고**
자기 이전 패스(0.215)보다도 나쁘다. Spiral의 초과(0.871)가 Warren의 미달(0.100)을
평균 안에서 상쇄한 것이다. 거리로 보면 상쇄가 아니라 **합산**이다.

구조적 수정: `balance.aggregate()`가 평균/중위/최대/RMS와 `n_balanced`를 돌려주고
승률 평균은 **"균형으로 읽지 말 것"** 라벨과 함께서만 출력한다.
`tests/test_balance.py`가 0.9/0.1 상쇄 사례를 고정한다.

### 6.2 search 단계 "최선기록"은 학습 없이도 목표에 닿는다

search 승률 하나의 SE가 0.102이므로 최선기록(달리는 최소값)은 **학습이 전혀
없어도 하강한다**. 각 시드의 초기 30 % 에피소드에서 재표집한 부트스트랩
귀무분포가 **6~7회**에 0.079(= anneal의 report 중위값)에 닿고 실제 프로브는
**5회·3회**였다 — 구별 불가. 0.000 교차로 보면 프로브 5 / **31** 대 귀무
10 / 29 로 시드 1은 오히려 **더 느리다**.

이것은 프로브만의 문제가 아니라 **모든 팔의 search 열**에 적용된다. 실측 예:
스킬 ON 맵 탐색 14런 중 **11런이 search에서 0.000**에 닿았으나 report는
0.004–0.225로 퍼졌다. 출발맵별 최선(0.096)은 최소값 선택으로 낙관 편향돼 있고,
편향 없는 값은 **전체 런 평균 0.121**이다.

### 6.3 채점 1회의 SE를 평균의 잣대로 쓰지 말 것

`sqrt(0.25/24) = 0.102`는 승률 **하나**의 SE이고, 두 승률 **차이**의 비대응
SE는 `sqrt(2·0.25/24) = 0.144`다. 코드·문서 6곳이 0.102를 후자로 잘못 적어,
경고하려던 바로 그 비교의 잡음을 **41 % 과소평가**했다. 또 그 0.102를 139개
평균의 잣대로 써서 §3.4의 실재하는 해킹 효과를 기각했다.

## 7. 말할 수 없는 것

- **"이 맵이 균형이다"는 항상 "이 휴리스틱 쌍에 대해 균형이다"** 라는 뜻이다.
  학습 정책 쌍에 대해서도 균형인지는 이 설계로 답하지 않는다 — 스터디 B의
  군비경쟁 관측(도망자 45→55→65 %)이 정책이 세대마다 승률을 옮긴다는 직접
  증거이므로, 이 한계는 가설이 아니라 **알려진 사실**이다
- H3의 생존 지표들은 공선적이고(PCA 미실시), 150개 중 47개가 승률 0.000이므로
  이것은 "승률을 설명한다"이지 "균형을 설명한다"가 아니다
- 판정 (A)는 "**이** 예산·보상·하이퍼파라미터에서"다. 4.6배로 50~80배를
  배제할 수 없다
- 맵 탐색 결과는 대부분 **스킬 OFF** 에서 측정됐다. 출시 설정(스킬 ON)에서의
  탐색은 §4.1의 14런뿐이고 시드 2개다
- `mapstudy/results/skill_tuning.json`의 스킬-ON 구간은 `DESTINY_MIN_DIST`가
  무력했던 엔진(캐시 세대 v3)에서 측정됐다. 권장 튜닝만 v4로 재측정했다
  (0.146 → 0.141); 나머지 4차 스윕 격자, 특히 밴드 관련 행은 **이력**이다
- 모든 스킬 수치는 휴리스틱 대 휴리스틱이다. 사람이 쥔 `rewind`는 다를 것이다
